# 灵动岛（DynamicIsland）架构设计

> 项目代号：DynamicIsland ｜ 目标平台：Windows 10 19041+ / Windows 11 ｜ 技术栈：C# / .NET 10 / WPF + Win32 互操作

## 一、技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 运行时 | .NET 10 | 本机已装 10.0.13 运行时；单文件发布体积小；内存低 |
| UI 框架 | WPF | 布局/文本/动画/数据绑定开箱即用，免去自绘控件体系 |
| 窗口 | Win32 P/Invoke（`HwndSource` 钩子） | 异形透明窗、点击穿透、贴顶吸附、不进 Alt-Tab |
| 通知 | WinRT `UserNotificationListener` | 系统级 Toast 读取，覆盖所有应用 |
| 媒体 | WinRT `GlobalSystemMediaTransportControlsSessionManager` | 统一接管所有播放器，无需逐个适配 |
| 音量 | Core Audio `IAudioEndpointVolume` | 系统主音量 + 静音，无第三方依赖 |
| 歌词 | LRCLIB（HTTP，免 Key） | 免费无需注册，支持同步 LRC |
| 天气 | Open-Meteo（HTTP，免 Key） | 免费无需注册，支持按经纬度取预报 |
| 硬件 | `PerformanceCounter` / `GetSystemTimes` / PDH / `NetworkInterface` | 零外部依赖，普通权限可读 CPU/内存/网速/GPU |
| 图标 | `IShellItemImageFactory` + `IShellLinkW` | 取 256px 高清图标、解析 `.lnk` 目标 |
| 配置 | `%APPDATA%\DynamicIsland\settings.json` | 明文易调试 |

### 为什么不选其他方案
- **WinUI 3**：异形透明窗仍需大量 Win32 互操作，且 WindowsAppSDK 部署较重
- **Tauri / Electron**：WebView 常驻内存高，不适合长期挂顶部；Rust 侧 WinRT FFI 成本高
- **纯 Win32 + Direct2D 自绘**：性能最好，但要自建整套控件体系，开发周期长

## 二、关键技术决策

### 2.1 窗口方案：固定大窗 + 内部动画（重要）
**问题**：WPF `AllowsTransparency=true` 时窗口走软件渲染；若逐帧改窗口 `Width/Height`，每帧都会重建渲染目标，导致卡顿闪烁。

**方案**：窗口尺寸**固定**为最大展开尺寸（`W=560, H=420`），真正的"岛体"是窗口内部的一个 `Border`，所有尺寸动画都在内部完成（`ScaleTransform` / `Width/Height` 动画）。窗口本身永不改变大小。

**代价**：固定窗口会覆盖屏幕顶部 560×420 区域，即使透明也会挡住鼠标 → 必须实现区域级点击穿透。

### 2.2 点击穿透
`HwndSource.AddHook` 拦截 `WM_NCHITTEST`：
- 命中岛体当前矩形（含圆角）→ 返回默认值（`HTCLIENT`），正常交互
- 其余区域 → 返回 `HTTRANSPARENT`，事件穿透到下层窗口

岛体矩形需实时维护（动画期间每帧更新），存于 `IslandHitRegion` 服务。

### 2.3 窗口样式
```
WS_EX_TOOLWINDOW   —— 不进 Alt+Tab、不显示任务栏按钮
WS_EX_NOACTIVATE   —— 点击不抢焦点（可选开启）
WS_EX_LAYERED      —— 分层窗口（透明前提）
WS_EX_TRANSPARENT  —— 不用（会整窗穿透），改用 WM_NCHITTEST
```
`Topmost = true`，贴顶居中：`Left = (ScreenW - W) / 2, Top = 0`。

### 2.4 动画
- 折叠 ↔ 展开：自定义弹簧（`CompositionTarget.Rendering` 每帧驱动），参数可调（stiffness / damping）
- 简单过渡：WPF `DoubleAnimation` + `CubicEase`
- 高刷屏：`CompositionTarget.Rendering` 天然跟随显示器刷新率

## 四、六大模块设计

### 模块 1：通知接收提示
- 服务：`NotificationService`
- 实现：`UserNotificationListener.Current` → `RequestAccessAsync()` → 每 1.5s 轮询 `GetNotificationsAsync(NotificationKinds.Toast)`
- 增量判定：记录已见过的 `Id` 集合（按 UserNotification.Id）
- UI：新通知到达 → 岛体短暂展开成通知卡（约 4s），显示应用图标 + 标题 + 内容；结束后恢复原状态
- 通知历史：保留最近 50 条，可在通知页查看
- **风险**：未打包应用可能被拒绝授权 → 若失败，降级为「本地推送接口」（HTTP 端口 + 托盘菜单手动推送），并提示用户开启通知访问权限

### 模块 2：音乐检测与控制
- 服务：`MediaService`
- 实现：`GlobalSystemMediaTransportControlsSessionManager.RequestAsync()` → `GetSessions()` 取当前会话
- 轮询 800ms：曲目标题/歌手/专辑、播放状态、时间轴（`GetTimelineProperties()`）
- 控制：`TryPlayAsync` / `TryPauseAsync` / `TrySkipNextAsync` / `TrySkipPreviousAsync` / `TryChangePlaybackPositionAsync`
- 封面：`TryGetThumbnailAsync()` → `IRandomAccessStreamReference` → `BitmapImage`
- 音量：`VolumeService` 控制系统主音量（滚轮在岛上滚动调节）
- 多会话：保留全部会话列表，可切换"当前接管"的播放器

### 模块 3：歌词显示
- 服务：`LyricsService`
- 流程：`GET https://lrclib.net/api/get?artist_name=&track_name=&album_name=&duration=` → 取 `syncedLyrics`
- 解析：`[mm:ss.xx] 文本` → `List<LyricLine>`，支持一行多时间戳
- 同步：以 `MediaService` 的 `Position` 为时钟，每帧（或 100ms）二分查找当前行
- UI：折叠态单行滚动；展开态显示 5 行，当前行高亮放大
- 缓存：`%LOCALAPPDATA%\DynamicIsland\lyrics\{hash}.json`

### 模块 4：日期与天气
- 时钟：`DispatcherTimer` 1s 更新
- 天气：`GET https://api.open-meteo.com/v1/forecast?latitude=&longitude=&current=temperature_2m,relative_humidity_2m,apparent_temperature,weather_code,wind_speed_10m&daily=...&timezone=auto`
- 定位：手动配置城市经纬度（默认北京）；可后续加 IP 定位
- 缓存：10 分钟；界面显示图标 + 温度 + 天气描述 + 3 日预报

### 模块 5：硬件监视器
- 服务：`HardwareService`，2s 刷新（可在岛上展开时提速到 1s）
- CPU：`PerformanceCounter("Processor", "% Processor Time", "_Total")` 或 `GetSystemTimes` 差值
- 内存：`GlobalMemoryStatusEx`
- 磁盘：`DriveInfo`
- 网速：`NetworkInterface.GetAllNetworkInterfaces()` 的 `IPv4Statistics.BytesReceived/Sent` 差值
- GPU：PDH 计数器 `\GPU Engine(*)\Utilization Percentage` 求和
- UI：环形/条形进度 + 数值，超 75% 橙色、超 90% 红色

### 模块 6：图标拖拽暂存与快速启动
- 服务：`LauncherService`
- 接收：WPF `AllowDrop` + `Drop` 事件，取 `DataFormats.FileDrop`
  - 仅接受 `.lnk` / `.exe` / 文件夹（也可放宽到任意文件）
- 解析 `.lnk`：`IShellLinkW` + `IPersistFile` 读 `TargetPath`、`Arguments`、`WorkingDirectory`
- 图标：`IShellItemImageFactory.GetImage(256x256)` → 转 `BitmapSource`
- 存储：`settings.json` 里存 `{Name, TargetPath, Args, WorkDir, IconCacheKey}`
- 交互：
  - 拖到岛上 → 岛体展开成图标坞，显示半透明预览格，松手落位
  - 点击图标 → `Process.Start(target, args, workDir)` 启动
  - 拖出图标 → `DoDragDrop` 生成 `.lnk`/文件到资源管理器
  - 右键 → 移除 / 在资源管理器中打开
- 布局：网格，每行 6 个，超过则分页

## 七、已知风险

| 风险 | 应对 |
| --- | --- |
| `UserNotificationListener` 未打包应用可能被拒 | 先实测；失败则做「本地推送 API + 降级提示」 |
| WPF 透明窗软件渲染掉帧 | 固定窗口尺寸；必要时给岛体加 `BitmapCache` |
| 系统时间轴与歌词不同步 | 以轮询到的 Position 做时钟，加延迟补偿配置 |
| GPU 占用 PDH 计数器语言依赖 | 用英文计数器名，失败则隐藏该项 |
| 拖放时窗口穿透干扰 | 拖拽悬停时临时取消 `HTTRANSPARENT` |
