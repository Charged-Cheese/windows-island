# 翻页修复进度

## 第一阶段：建立可重复基线

这一阶段增加诊断能力，不改变滚轮、队列、尺寸或曲线行为。

### 使用方法

```powershell
dotnet build src/DynamicIsland/DynamicIsland.csproj -c Release
python tools/paging_baseline.py --exe src/DynamicIsland/bin/Release/net10.0-windows10.0.19041.0/win-x64/DynamicIsland.exe --out artifacts/paging-baseline-stage1 --repeats 3
```

运行前退出其他灵动岛实例。输出目录必须不存在，避免覆盖旧基线。脚本启动自己的进程，在独立数据目录中关闭天气、硬件、通知等可选服务，测试结束后退出自己的进程。它不会移动鼠标或改正式配置。

`DI_PAGING_LOG` 启用内存采样；未设置时不注册采样回调。采样期间不格式化 CSV、不写盘。脚本在测量窗口之外通过 `probe:flush` 落盘，正常退出也会补写。最多缓存 100,000 条，达到上限后停止记录；长时间手工采样应主动落盘。

仅探针启用时支持 `probe:wheel:N`、`probe:mark:NAME` 和 `probe:flush`。合成滚轮直接调用实际 `HandleWheel`，用于隔离输入算法和动画行为，不能证明真实设备的 delta 分布、WPF 事件路由或硬件延迟。

### 记录和口径

- `paging.csv`：单调时间、输入 delta、余量、待执行步数、队列长度、页面位置与目标、动画状态、岛体宽高和尺寸收敛状态、出场/入场页的实际布局加变换位置与透明度。
- `summary.json`：每项三轮结果、程序集 SHA256、隔离配置、CPU 原始值和扣除基线后的值。
- 单格、三格（输入间隔 46.5ms）、反向、两端边界、三个 80 delta、单次 360 delta、动态到日历、未满刻度反向。
- 页面尾延迟：最后一次输入后，页面位置最后一次偏离最终位置超过 0.5 DIP 的时间，存在一个采样间隔左右的误差。这里不包含透明度、缩放和阴影，不称为“画面完全停止”。
- 逻辑尾延迟：最后一次输入到最后一个 `step_finish` 事件。尺寸尾延迟单独统计。
- CPU：从首次输入起分别统计实际约 240ms 和 900ms 窗口，扣除切页前同长度静止窗口。保留原始值和负的净值，暴露后台任务噪声，不裁成零。
- 帧间隔：渲染回调间隔，报告最大值和超过 33ms 的数量；不将其直接解释成 CPU 运算时间或显示器呈现时间。

### 限制

进程 CPU 包含探针开销、媒体会话更新及其他后台工作。即使关闭可选服务，仍有媒体会话等任务，因此小样本 CPU 数据只用于发现趋势，不能直接归因于布局或阴影。测试使用空历史列表，不能验证 30 项列表或“固定尺寸提升 3.4 倍”。页面尺寸与位置可以验证状态逻辑；裁剪、闪烁和真实手感需要后续逐帧目视验证。

原始报告中的 30% 是 16.7ms 代入 Quint 得到的理论进度，不是这里测得的首个显示帧。当前基线也不采用该表述。

### 本机基线（2026-11-01）

Release 编译通过，9 个场景各运行 3 轮，共 27 项记录完整，观察窗口内均收敛。原始文件在 `artifacts/paging-baseline-stage1-final/`（本地生成，不提交）。以下是三轮中位数，不能与像素差探针的“画面停”直接混用。

| 场景 | 最后输入后页面位置尾延迟（0.5 DIP） | 最后输入后动画逻辑尾延迟 |
|---|---:|---:|
| 一格 | 147.9ms | 247.9ms |
| 三格，输入跨度约 93ms | 551.7ms | 651.5ms |
| 一格后反向 | 344.1ms | 444.0ms |
| 动态到日历 | 146.4ms | 245.2ms |

输入缺陷三轮均复现：三个 `-80` 只从第 1 页走到第 2 页（应到第 3 页）；一次 `-360` 也只到第 2 页（应到第 4 页）；先 `+100` 再 `-120` 停在第 2 页，未响应新的完整反向刻度。

CPU 分窗测量已完成，但部分净值为负，且 240ms 与 900ms 的净值差异明显，因此本阶段只确认窗口口径和噪声，暂不据此宣称“一个核满载”或某项优化的性能倍数。

编译仍提示原有 SQLite 原生依赖的 NU1903 警告；本阶段没有调整依赖版本。
