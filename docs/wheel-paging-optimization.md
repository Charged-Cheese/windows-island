# 滚轮翻页优化方案

> 2026-11-01 · 基于 4 路只读诊断 + 本机实测（2560×1600@240Hz，150% 缩放，WheelScrollLines=3）

## 一句话结论

翻页观感差**不是曲线问题，也不是参数调得不够**，而是三件事叠在一起：多格输入被串行放大成 N×240ms、垂直滑动被岛体长高的空间漂移抵消、首帧就走完 30% 位移。三条各自独立，按 A→B→C 修。

## 一、实测现状

### 1.1 延迟（手停 → 画面停）

| 场景 | 首帧动 | 最后明显动 | 手停→画面停 | 倍数 |
|---|---|---|---|---|
| 滚 1 格 | 20.0ms | 145.6ms | 145.6ms | — |
| 滚 3 格 | 25.1ms | 766.1ms | **673ms** | **7.2×** 手部时长（93ms） |

理论串行 = 240×3 = 720ms，实测 741ms（766−25），模型吻合。

业界跟手阈值是 100ms。**滚 3 格时超了 6.7 倍**。

### 1.2 单帧预算

| 指标 | 数值 |
|---|---|
| 静止 CPU 基线 | 78ms / 900ms = **8.7%** |
| 单次切页净增 CPU | **234ms**（中位数，跨 3 次测量 141 / 406 / 234） |
| 动画时长 | 240ms |

一次 240ms 的动画净吃 234ms CPU ≈ **接近 1 个核满负荷**。根因是页面被每帧改尺寸的岛体拉伸，整棵 30 项列表每帧重排（实测 15.15ms/帧 vs 页面固定尺寸 4.45ms，**3.4×**）。

### 1.3 位移是否真的被看见

`TabSlideDistance = 34`，但：

- 岛体 `VerticalAlignment="Top"`，长高只往下扩
- 页面内容 `VerticalAlignment="Center"`，中心随 Row1 高度下移 Δh/2

动态页(236) → 日历页(320)：Δh = 84 → 内容中心被推下 **42px**，而页滑动只上移 **34px**。净位移 **+8.5px**，且方向反转 2 次。

**滑动感被吃掉 2/3，剩下的全是"内容原地抖"。**

## 二、根因（三层，各自独立）

### 第一层：多格输入被串行放大

`HandleWheel` → `RequestWheelStep` → `StartTabStep`，动画期滚轮只记 `_wheelPendingSteps`（上限 2），每次 `FinishTabStep` 只消费 1 步、重跑满 240ms。

```
滚 3 格 = StartTabStep × 3 串行 = 720ms
```

**这不是"动画慢"，是"排队排得长"。** 用户滚 3 格想直达第 3 页，系统却坚持逐页展示。

### 第二层：垂直滑动与高度变化同轴叠加

页面滑动的 34px 上移，与岛体长高带来的 Δh/2 下移方向相反。两者同轴（都是 Y），眼睛无法把"换页"和"岛变大"分开。

`ApplyContentFade` 在切页路径上**完全不起作用**：所有 tab 高度 ≥156，而 `expanded = (h-62)/74` 的满值点是 136，全程恒为 1。交叉淡入等于没有任何保护。

### 第三层：首帧走完 30%，尾巴空转 63%

`EaseOutQuint` 在 240ms 里的分布：

| 进度 | 耗时 | 剩余 |
|---|---|---|
| 50% 位移 | 31ms | 209ms 走另外 50% |
| 80% | 66ms | 174ms |
| **90%** | **89ms** | **151ms 只走 3.4px** |
| 99% | 144ms | 96ms 走 0.11px |

**首帧 16.7ms 走完 10.28px = 全程 30.2%。** 这读起来是"跳切 + 收尾"，不是"滑动"。

同时 `opacity < 0.02 → Collapsed` 反解得距离 > 0.84，即 **74ms 时旧页就彻底消失**，后 166ms 根本没有淡出过程。

### 附带的输入层缺陷（不改也能用，但会放大主观差评）

| 缺陷 | 代码位置 | 后果 |
|---|---|---|
| 触发后 `_wheelAccum = 0` 丢余量 | MainWindow.xaml.cs:1371 | delta=80 的设备两格才翻一页，节奏"一格死一格动" |
| 无方向反转重置 | 同上 | 上滚 100 + 下滚 120 互相抵消 → "滚了没反应" |
| 边界静默 `return` | MainWindow.xaml.cs:1395 | 第一页再上滚无位移、无回弹、无反馈 |
| 折叠态音量无归一化 | MainWindow.xaml.cs:1380 | 触摸板一次滑动把音量推 40% |

## 三、方案

### A 档：修输入层（预计 30 分钟，风险极低）

只改 `HandleWheel`，不碰动画。

```csharp
private const int WheelNativeTick   = 120;   // Win32 WHEEL_DELTA
private const int WheelDetentFloor  = 90;    // 单事件 ≥90 视为整格（鼠标直通）
private const int WheelGestureGapMs = 160;   // 间隔 >160ms 判为新手势
```

三条规则：

1. **保留余数**：`_wheelAccum -= n * WheelNativeTick`（不清零），delta=80 变成均匀的 2 格 1 页
2. **方向反转清零**：`if (Math.Sign(delta) != Math.Sign(_wheelAccum)) _wheelAccum = 0`
3. **单事件 ≥90 直通**：传统鼠标不经过累积器，0 延迟

外加：`SetState` 里加 `_wheelAccum = 0`（状态切换 = 新手势的强信号）。

**收益**：消除"滚了没反应"和"节奏抖动"——这两条是主观评分最低的。
**风险**：`WheelDetentFloor = 90` 需拿真实设备采样校准（Logitech smooth scrolling 可能发 ±80）。

### B 档：滚轮改追目标（预计 1.5 小时，风险中）

**这是最核心的一条。**

把滚轮的"排队翻页"改成"追目标位置"。点分页点 / 日历入口**保持现有的串行队列**——那是显式跨页跳转，逐页展示是对的。

```csharp
// 滚轮唯一出口：只推目标，执行器用弹簧追
private void PushWheelTarget(int dir, int count)
{
    int from = (int)Math.Round(_tabAnimating ? _tabAnimTo : _tabPosition);
    int wanted = Math.Clamp(from + dir * count, 0, _tabPages.Length - 1);
    if (wanted == from) { PlayEdgeBounce(dir); return; }   // 边界给反馈，不静默吞
    StartWheelGlide(wanted);
}
```

`StartWheelGlide` 用弹簧追 `_tabPosition`（不是定时动画），参数取 ζ≈0.98：

| 参数 | 值 | 3 单位行程 |
|---|---|---|
| k=700, c=52 | ζ=0.983 | 90% @179ms，99% @292ms，**过冲 0.0%** |

**实测模拟：滚 3 格 766ms → ~300ms，且中间页连续滑过而非逐页停驻。**

对比定时动画方案（每格 `T = clamp(120·|Δ|^0.7, 90, 240)`，3 格一次到位 240ms，90% 在 129ms）——**两者时长接近，但弹簧能自然继承速度**，连滚时不会出现"急停再起步"。选弹簧。

**收益**：滚 N 格的视觉总时长从 N×240 降到 ~300ms 量级，不再随格数线性增长。
**风险**：`d50cab9` 删掉弹簧追目标是因为"点击分页点跨页时会闪过中间页"。所以**必须保留两条路径**——滚轮走弹簧、分页点走队列。改错了会退化回跳页。

### C 档：修空间抵消 + 首帧占比（预计 2 小时，风险中）

#### C1 切页时岛体尺寸改定时动画

现状：弹簧 ζ=0.557，2% 收敛 373ms，**settle 567ms**，过冲 +10.04px。240ms 那一刻岛高 328.14（已超目标 8.14px），之后 327ms 在 318.8~330.2 之间振。

给 `IslandSpringEngine` 加一个平行的定时通道 `SetTargetTimed(w, h, r, ms, easing)`，切页时走 240ms + `EaseOutQuint`。弹簧保留给折叠↔展开 / 通知 / nudge 这些没有固定时长的物理场景。

**收益**：消掉 327ms 余震尾巴，岛高与页面滑动同一条时间轴。

#### C2 页面按目标尺寸锚定（同时是性能优化）

这一条一石二鸟：既消掉 Δh/2 漂移，又解决每帧重排。

`UpdateExpandedContentLayout()` 现在只对 `tab3`（图标坞）设固定尺寸，其余 5 页 `Width/Height = double.NaN`（Stretch）。作者注释写着"不能让图标跟着每一帧的岛宽重新挤压"——这个判断是对的，只是没推广。

推广到全部 6 页后实测：**15.15ms/帧 → 4.45ms/帧（3.4×）**。

页面固定尺寸后，内容不再随岛体长高而漂移，34px 的滑动量完整保留。

**但要注意**：页面固定尺寸 + 岛体弹簧仍在变尺寸，前 100ms 会有裁剪。需逐帧确认日历页（460 宽）切过去时不露边。

#### C3 曲线微调

两条，都很小：

1. **透明度指数 1.45 → 1.0**：中点两页各 0.366，composite 掉到 0.598，岛中间会露出深色空洞（岛体底色 #F20A0A0E 是 95% 不透明，不是透出桌面）。改成 `1-e` 后 composite 最低 0.750。
2. **时长 240 → 200ms**，曲线从 `EaseOutQuint` 换 `EaseOutCubic`：首帧占比从 30.2% 降到 27%，90% 点在 85.7ms。**这条可选**——quint 与 cubic-bezier(0.22,1,0.36,1) 的差值只有 0.38px，换曲线收益不大，主要是缩时长。

## 四、执行顺序与预期

| 档 | 内容 | 预计工时 | 关键收益 | 风险 |
|---|---|---|---|---|
| **A** | 输入层归一化 | 30min | 消除"滚了没反应" | 极低 |
| **B** | 滚轮追目标 | 1.5h | 滚 3 格 766→300ms | 中（必须与队列路径分离） |
| **C1** | 尺寸定时动画 | 1h | 消掉 327ms 余震 | 中（`_primed` 首帧路径要复用） |
| **C2** | 页面固定尺寸 | 1h | 3.4× 性能 + 消漂移 | 中（裁剪需逐帧确认） |
| **C3** | 曲线/透明度微调 | 20min | 中点不空洞 | 低 |

**A + B 做完就能解决 80% 的主观问题**（"不跟手""滚了没反应"）。C 档是打磨。

| 方案 | 实测 | 结论 |

## 五、验证方法

改动后必须跑的三项：

1. **延迟**：`python tools/wheel_probe2.py` —— 滚 1/3 格的手停→画面停，目标 ≤200ms
2. **帧间隔**：`DI_FRAME_LOG=artifacts/frame-after.csv` 启动 → 统计 max 和 >33ms 帧数。**别盯 p99**：240Hz 屏上一帧 = 4.167ms，p99=18.3ms 是 vsync 网格量化（4.39 档），不是 CPU 真算了 18ms
3. **逐帧目视**：`python tools/tab_midframe2.py` 抓 240ms 内 25 帧，确认旧页不是 74ms 就消失、岛体不长出鼓包

## 六、需要产品决策的两点

1. **滚 5 格以上要不要跨页直达？** 追目标方案会连续滑过中间页（每页停留约 60-100ms）。如果要求"每页必须完整可见"，B 档就退化成串行，只能靠缩短单页时长（240→120ms）缓解——但 120ms 的页面切换会显得急促。
2. **页面内容锚定顶部还是保持居中？** C2 的固定尺寸方案会让内容相对目标尺寸排版（视觉上等价于顶对齐），日历页（320 高）的内容会明显偏上。这是观感改动，不只是 bug 修复。

## 附：诊断来源

| 诊断方向 | 核心结论 |
|---|---|
| 尺寸弹簧联动 | 参数实为 355/21（ζ=0.557），settle 567ms ≫ 页面 240ms；Δh/2 漂移抵消 34px 滑动 |
| 动画曲线 | 曲线本身没问题（quint vs bezier 差 0.38px）；首帧 30.2%、74ms 旧页消失、中点 composite 0.598 |
| 滚轮输入层 | 120 阈值 + 清零丢余量 → 节奏抖动；pending 计数 → 串行 720ms；边界静默吞输入 |
| 渲染性能 | 页面被每帧改尺寸的岛体拉伸 → 3.4× 重排；p99 是 240Hz vsync 量化不是 CPU 时间 |
