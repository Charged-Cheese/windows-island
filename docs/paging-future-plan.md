# 翻页后续开发计划：第五、六阶段

状态：第五阶段已实现并完成自动复测，桌面逐帧与真实鼠标验收待完成；第六阶段待开发。v1.0.4 发布包仍仅包含第一至第四阶段；第五阶段改动尚未发布。

已完成内容、第五阶段实测和未验证项见 [阶段记录](paging-repair-progress.md)。第五阶段完成验收后，再进行第六阶段；每阶段单独提交、汇报。

## 当前版本交接基线

- 输入按 120 delta 归一化，保留余数，反向及状态切换清余量。
- 滚轮追最新目标，k=700、c=52，解析解积分，连滚继承速度；没有滚轮待执行队列。
- 点击分页点、日历入口仍逐页 240ms。两种路径接管时位置连续，滚轮接管会清除旧点击队列。
- 六页固定各自尺寸并顶部锚定；媒体页头、正文、展开封面同属媒体页；外层岛体负责裁剪。
- 切页宽高/圆角已接入独立 240ms 定时通道，从当前实际尺寸重定向，到期准确落位；开合、通知仍用弹簧，轻弹独立收尾。240ms 是通道时长，完成事件要等下一次实际渲染回调，不等于显示器呈现时间。
- 透明度仍为 `Pow(1 - smoothstep(distance), 1.45)`，小于 0.02 时隐藏；点击仍用 EaseOutQuint。
- v1.0.4 基线的单格页面位置尾延迟约 229ms，未达 200ms 目标；第五阶段没有调整页面弹簧/点击曲线，新的回调测量见阶段记录。真实设备手感没有完成验收。

## 第五阶段：切页尺寸动画同步（实现与自动复测完成，桌面验收待完成）

### 目标

消除切页后岛体继续振荡的尾巴，让尺寸变化在确定时间结束；保留开合、通知和轻弹的物理反馈，以及第四阶段固定页面布局。

### 开发内容

1. 在 `Infrastructure/IslandSpringEngine.cs` 增加尺寸定时通道，例如 `SetTargetTimed(width, height, radius, duration)`。宽、高、圆角按同一单调时钟插值；到期准确落在目标，终点不留残余速度。先以 240ms 验证，不同时缩短页面动画。
2. 复用 `_primed` 初始化规则：启动首次直接落位。定时尺寸与 `_nudge` 保持独立，尺寸结束不能提前停止仍在运动的轻弹；只有所有活动通道结束才退订 Rendering。
3. 切页时接入定时尺寸：点击每步以该步起点开始；滚轮每次接受新目标，以当前实际尺寸重新接向最新目标，不能排队重播。滚轮页面追赶约 300ms，尺寸暂定 240ms，两者共享目标更新时间，不能把它们错误解释成必须同一帧结束。
4. 处理通道接管：定时 → 弹簧、弹簧 → 定时、定时 → 新目标均从当前实际宽高/圆角衔接，至少保证位置连续。若交接处速度突变可见，再引入带初速度的插值；不能为了保速重新引入过冲。
5. 折叠、展开、通知优先按状态机接管尺寸目标；不要让已失效的切页尺寸在收起途中重新展开岛体。保留命中区、HUD、封面 morph、拖动和悬停规则。
6. 系统关闭动画时，切页内容与尺寸都应直接落位。不要出现页面已到位、岛体仍慢慢变形的分裂行为。
7. 扩展诊断：记录尺寸模式、目标尺寸、目标更新时间及完成/取消事件。兼容原 CSV 分析，仍把页面尾延迟与尺寸尾延迟分开。

### 主要文件

| 文件 | 预计改动 |
|---|---|
| `src/DynamicIsland/Infrastructure/IslandSpringEngine.cs` | 定时通道、模式接管、首次落位、结束条件 |
| `src/DynamicIsland/MainWindow.xaml.cs` | ActiveTab/状态机的尺寸目标路由 |
| `src/DynamicIsland/MainWindow.WheelPaging.cs` | 目标更新时间与尺寸通道协调 |
| `src/DynamicIsland/MainWindow.PagingDiagnostics.cs` | 尺寸目标和结束事件 |
| `tools/paging_baseline.py`、相关 SelfTest | 中断、反向、尺寸收敛与降低动效验证 |

### 验收标准

- 动态↔日历、媒体↔其他页、图标坞↔其他页的尺寸，在最后目标更新后 240ms 加一个实际渲染回调间隔内准确落位；之后不再超调、振荡。
- 连续三格、五格不生成 N 段尺寸动画；反向不瞬跳，旧尺寸目标不在后面补播。
- 切页中移出/移回、通知到达、拖动历史滑块、右键菜单开关、系统降低动效均不破坏最终状态、命中区和 HUD。
- 页面宽高与锚点仍固定；30 项列表末尾可达，图标坞保持六列；完成后日历文字不被截断。
- 逐帧核对日历变宽和短页收缩时的边界：允许岛体在变形过程中裁剪内容，但不能露出岛外像素、在终态残留裁剪或使内容突然整体位移。
- 现有滚轮/点击接管与最终页断言全部通过。记录真实尺寸结束时间，不以像素差阈值代替尺寸通道完成事件。

## 第六阶段：透明度、时长与真实体验打磨

### 目标

在布局和尺寸稳定后，解决中段内容过暗、旧页过早消失、单格收尾偏长；完成实际窗口、真实鼠标和不同刷新率的验收。

### 开发内容

1. 重新抓取当前版本的淡出时间线，不能继续引用旧 Quint 路径的“74ms 消失”作为滚轮现状。
2. A/B 比较透明度指数 1.45 与 1.0，检查中段文本可读性及空洞感；评估 `<0.02` 隐藏阈值是否过早。只在贡献已不可见时收起子树，避免透明页面截获点击。
3. 理论上两层同像素均有不透明内容时，指数 1.0 的中点合成覆盖率为 0.75；页面大多透明，不能把该数值当作整块界面的实测亮度。必须检查实际像素和观感。
4. 单独评估滚轮弹簧与点击动画。滚轮保留目标追赶和速度继承，通过实测决定是否调整 k/c；点击再比较 240ms/200ms、Quint/Cubic，不把已经奏效的双路径调度改回串行。
5. 验证封面、页头、歌词、通知列表和日历在同一页内一起移动/淡出，换歌动画不覆盖页面透明度。
6. 检查深浅主题、四档材质与动画风格，重点覆盖长标题、无媒体、空列表、30 项通知、剪贴板图片及六行日历。
7. 使用实际窗口和真实鼠标/高精度设备采样 delta。继续遵守标准累计规则；没有设备证据时不增加“≥90 就算一格”的特例，也不随意吞掉小刻度。

### 验收标准

- 沿用相同的 0.5 DIP 页面尾延迟口径：单格争取 ≤200ms，三格/五格不随格数成倍增长；实际未达标必须记录差距，不能替换阈值来制造改善。
- 逻辑结束、位置稳定、尺寸稳定、透明度结束分别报告；首个渲染回调不冒充首个显示帧。
- 连滚、快速反向与两种输入接管时无跳位、回放旧请求、明显空白或中点突然变暗。
- 旧页退出与新页进入均可辨识，终态清晰且点击正确；无残留透明页面和不可点击按钮。
- 记录帧间隔分布、最大值及 >33ms 数量；CPU 分别保留 240ms/900ms 原始值与静止基线，承认后台噪声，不据此直接断言布局或阴影占用一个核。
- 实际窗口中完成开合、切页、滚动条拖动、日历、媒体控制与换歌验收；如设备/播放器无法触发某项，明确标记未验证。

## 不应重新尝试的方向

按已有诊断，暂不启用软件光栅下的 BitmapCache，不把阴影搬到静止兄弟 Border，也不把阴影淡到接近零当作停止模糊计算。将来若重新考虑，必须有新的对照证据。第五、六阶段均不包含重写渲染器或调整依赖版本。
