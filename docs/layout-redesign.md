# 岛内容布局重排 — 方案（讨论稿）

> 目标：在已完成的 P0–P7（材质四档 / 去卡片 / 性能止血 / 指针反馈）基础上，重排 8 个模块的内容布局，
> 决定哪些合并、哪些拆细，统一视觉语言后再美化。
> 本文只给方案，不含实现；确认后再改代码。

## 2. 合并决策

### 合并 1：媒体 + 歌词 → 「媒体」页（建议采纳）

理由：两页共用同一个 `MediaHeader`、同一份 SMTC 数据、同一套尺寸档；歌词只是「内容区在有歌词时的形态」。
现在用户为了看歌词要多点一次分页点，而媒体页在没有歌词时又在显示「暂无歌词」空状态 —— 一页能说完的事占了两页。

落地方案：
- 内容区自动切换：`HasLyrics` 为真 → 4 行歌词；为假 → 频谱 + 「暂无歌词」提示（保留现在的视觉）。
- 手动强制切换保留一个入口：长按封面或点击页头的「歌词」图标，在「歌词 / 频谱」间锁定。
- 净收益：少一页、少一次点击、尺寸档从 188 收到 176（已做）。

### 合并 2：通知 + 剪贴板 → 「动态」页（建议采纳）

理由：两者都是「带时间戳的条目列表」，行高、图标区、时间列、空状态完全同构；现在占两页、两个分页点。
合并后页内用两个分段 chip 切换，列表逻辑与滚动条自检都不用改（复用同一套 ItemsControl 模板）。

落地方案：
- 顶部页头左侧「动态」，右侧「清空」；下方一行 2 个分段 chip：通知 / 剪贴板（100×22，选中态用强调色底）。
- 行结构统一：图标 26 / 标题 11.5 / 正文 10 / 时间 9 右对齐；未读条目左侧 2px 强调条。
- 尺寸沿用 236（够 5–6 行）。
- 净收益：少一页、两个列表共用一套美化。

### 不合并的模块

- **天气 vs 性能**：数据源、更新频率（10 分钟 vs 1 秒）、语义都不同，合并会让「性能」页每秒都在重绘天气。保留两页，但统一「指标卡」视觉。
- **图标坞**：独立启动器语义，与列表无关。
- **日历**：唯一 460 宽的页面，横向信息密度最高，不能被塞进 384。

### 结论

**8 页 → 6 页**：媒体、天气、性能、图标坞、动态、日历。

需要连带改的地方（已评估）：
- `MainWindow.xaml.cs` 的 `TabSizes`（6 项）、`TabShowsMedia`（只剩 0）、`ApplyTabTransition` 的页数组、`HandleWheel` 的 `Clamp(..., 0, 7)` → `0, 5`。
- 分页点从 8 个减到 6 个（XAML 里 `TabDotIndicator0..7` 删两个）。
- `IslandViewModel.ActiveTab` 的所有 `== 4 / == 7 / == 3` 之类分支要按新索引重排（当前通知=4、剪贴板=6、日历=7）。
- 自检：`HistoryScrollbars.SelfTest` 直接解析 XAML 找 ScrollViewer，合并后仍是一个列表容器，预计不受影响，但要在 P8 阶段跑一遍确认。

## 4. 跨页统一项

- 所有页头结构、字号、强调条尺寸一致（现在 5 处是复制的，下一步可抽 `IslandPageHeader`，但会碰到解析 XAML 的 41 项自检，放在最后且先改自检）。
- 空状态统一：图标 24（三级灰 0.45）+ 文案 10.5 + 可选一行操作提示。
- 列表行统一模板（动态页两块共用），减少两套 hover 触发器。
- 所有交互元素保留 P6 的悬停 1.15 / 按下 0.90。

## 5. 动效补充

- 页内切换（歌词/频谱、通知/剪贴板）：160ms 淡入 + 4px 位移，复用现有 `AnimateCalendarGrid` 的模式。
- 分段 chip 选中态：共享一个 150ms 滑块（两层 Border 叠放，位移 + 宽度过渡）。
- 列表首屏进入：最多 3 行 stagger 20ms，只在切页时跑一次，滚动不触发。

**未做项与原因**

- 图标坞「空位虚线格」：需要把占位项混进 `UniformGrid` 的数据源（真实图标与占位共用模板、按类型切样式），改动面比收益大；当前页头已有「拖入快捷方式」提示、完全为空时还有居中引导语，缺口不明显。
- 动态页列表底部渐隐：岛体是半透明玻璃，渐隐遮罩需要精确匹配下方渐变，做不好会露出一条色带；保持硬裁切更稳。
- 分页点位置随页面宽度移动（日历 460 宽时点右移）：这是「点贴着岛右缘」的必然结果，暂不改；实际点击有指针反馈兜底。
